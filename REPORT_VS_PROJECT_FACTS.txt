USER SCENARIO 2 — Book travel package
================================================================================

"Issue Booking Package composite" as distinct box
  REWORD — Orchestration is inside the booking service (POST /book-package and
  POST /booking), not a separately named container.

Order: payment → confirm flight/hotel → redeem → earn → POST /bookings last
  WRONG vs CODE — Actual order (simplified):
  - INSERT booking PENDING (early persistence)
  - POST flight reserve-seat
  - POST hotel hold-room
  - GET loyalty .../points and POST .../redeem (BEFORE payment)
  - POST payment .../process
  - PUT confirm seat/room + availability CONFIRMED
  - UPDATE booking CONFIRMED
  - POST loyalty .../earn (after confirm)
  - notify (AMQP / manual) + SMS

Final step POST Booking /bookings to create row
  WRONG — Booking row is created at the start (PENDING), not at the end.

Traveller: GET /traveller/{id} → TravellerDB
  SIMPLIFY — Profiles via OutSystems REST or local demo through booking
  traveller routes; not simple MySQL TravellerDB in the running stack.

Payment body { amount, paymentDetails } to live Stripe
  SIMPLIFY — Body uses bookingID, amount, currency; payment is simulated in repo.
