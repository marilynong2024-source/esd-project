TRAVELLER PROFILES (OutSystems REST, not in this repo’s MySQL)
--------------------------------------------------------------------------------
  • Base URL: env TRAVELLER_PROFILE_BASE_URL (see .env / docker-compose).
  • List profiles for a member: GET {BASE}/byaccount/{customerID}
  • Create / update / delete: booking service proxies under /travellerprofiles/*
    (UI calls these via /api/booking/...).

  Traveller profile Ids are allocated in OutSystems. Use the byaccount response
  when attaching profiles to a booking (step 2 — Travellers).

  If TRAVELLER_PROFILE_LOCAL_DEMO=true, profiles are in-process only (no cloud).

--------------------------------------------------------------------------------
UI BOOKING FLOW (no preset picker)
--------------------------------------------------------------------------------
  • Use “Reset form” on step 1 to clear the wizard and restore default route/trip
    window; then choose member/guest, bundle, hotel, flight, and pay.
  • Curated bundle cards and trip windows are static catalog options in the UI,
    not extra accounts.
