SIGN-IN (POST /account/login)
--------------------------------------------------------------------------------
  • Email: one of the addresses below (case-insensitive).
  • Password: must match the password in the table (demoPass1 … demoPass12).
  • Accounts loaded from account/app.py in-memory seed, unless
    ACCOUNT_STORE_PATH JSON exists (then merged; add "password" per user there).
  • New sign-ups (POST /account/signup): choose your own password (stored for login).

LOYALTY (loyalty/app.py — in-memory; customerID must match account)
--------------------------------------------------------------------------------
Tier rules: Bronze 0–1 completed trips, Silver 2–4, Gold 5–9, Platinum 10+.
Coins are cents (100¢ = S$1 off on Pay step).

New sign-ups (POST /account/signup or POST /account): the account service calls
  POST /loyalty/{id}/init-new-account so that id starts Bronze / 0 / 0 (never inherits
  demo rows for the same numeric id).

Loyalty is keyed by customer ID, not email. If you change your email under My profile,
  you keep the same ID and the same wallet. Demo IDs 1–12 have pre-set tiers in
  loyalty/app.py for the seeded emails above — signing in as ivy.ng@example.com is ID 9
  (Platinum in the demo table), not the same as a new signup unless your stored
  accounts.json reused that id.

TRAVELLER PROFILES (OutSystems REST, or LOCAL_DEMO in booking/traveller_os.py)
--------------------------------------------------------------------------------
  • Live cloud: GET {BASE}/byaccount/{customerID}
  • TRAVELLER_PROFILE_LOCAL_DEMO=true: in-memory rows in traveller_os.py (Ids 1–17
    seeded; new profiles get Ids from 251+).

  Match booker lead: session displayName vs FullName (spacing/punctuation ignored)
    — see UI behaviour for “booker as lead”.
